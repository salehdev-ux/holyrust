# DECISIONS.md — Architectural Choices (SPEC Part 6: "A decision not in DECISIONS.md did not happen")

| ID | Decision | Rationale (one line minimum) |
| :-- | :-- | :-- |
| D001 | Host compiler language: **Rust** (self-hosting later). | Mandated by SPEC Phase 0 Task 2. |
| D002 | Toolchain: rustup stable 1.99.0 + gcc 12.2 installed under `/opt` (outside workspace); `tools/setup_env.sh` re-bootstraps a fresh sandbox. | Sandbox had no toolchain; keeping it out of `/home/user` keeps the persisted snapshot small and repo-focused. |
| D003 | **JIT backend: self-contained direct x86-64 machine-code emitter + `mmap(PROT_EXEC)`** — the SPEC §2.2D fallback *family* — instead of Cranelift. Recorded as DEGRADE (OPEN_QUESTIONS Q1). | (a) Cranelift pulls ~60 transitive crates, contradicting §1.1(3) "no external dependencies, one small self-contained compiler" and Principle 5 (self-containment); (b) the spec's own fallback ("emit x86-64 … `mmap` + execution") sanctions in-memory machine code without LLVM; (c) direct emission (no `cc` subprocess) removes per-statement process-spawn latency (Principle 2, ≤50ms gate) and removes the runtime dependency on an external assembler (Principle 5); (d) full control of the custom calling convention needed by L2/L3/L9 (stack-arg convention → `argc`/`argv` are trivial, `throw` restores rsp/rbp directly, function calls go through swappable indirection cells enabling Phase 6 hot-patching); (e) generated-code speed is an explicit non-goal (§1.3). Contingency: literal `cc`+asm path stays available (gcc installed) if the emitter is ever blocked — would be a further DEGRADE. |
| D004 | Single cargo crate `holyrust` (binary `hr`) with modules `hr_lexer/hr_parser/hr_check/hr_codegen/hr_runtime/hr_shell` + `diag`. | SPEC names components, not crates; one crate keeps `cargo test` as the single runner (Phase 0 Task 3) and avoids workspace overhead. Module names mirror spec component IDs 1:1. |
| D005 | Zero `[dependencies]` and zero `[dev-dependencies]`; hand-rolled seeded fuzz harness and file-based snapshot tests. | §1.1(3) + Principle 5; also removes network fragility from CI. "Fuzz with 10k random inputs" (Phase 1 Task 3) does not require a fuzzing crate. |
| D006 | Calling convention (internal, all generated code): args pushed right-to-left on the machine stack (cdecl-style); callee frame `push rbp; mov rbp,rsp`; arg_i at `[rbp+16+8i]`; return value in `rax` (F64 returned as IEEE-754 bits in `rax`); register `r15` permanently holds the runtime-context pointer; all runtime/builtin calls are indirect through a fixed function table in the context. | Makes `argc`/`argv` (L3) a direct view of the arg area; avoids GOT/PLT/relocations entirely (position-handled by our own fixups); reserved `r15` is safe because generated code only calls generated code or runtime functions (extern "C" preserves callee-saved regs); F64-in-rax keeps one uniform return path. |
| D007 | String type: built-in `Str` = pointer to heap block `{header, len, bytes…, NUL}`; literals are **immortal-copy** (assignment from a literal copies the reference without move-invalidation). | SPEC L5/L8 imply strings but name no type (OPEN_QUESTIONS Q3); immortal literals avoid absurd "use-after-move of a constant" while keeping move semantics for program-created `Str` values. |
| D008 | Copy vs Move types: all scalars (`U0,U8..U64,I8..I64,F64`) are **Copy**; `Str` and `class` values are **Move** (assignment/pass-by-value/return moves and invalidates the source header). | Rust's own Copy-type carve-out; keeps L8 meaningful without runtime headers on every integer (perf note §2.3); documented in LANG_SPEC §7. |
| D009 | Borrow syntax: HolyC pointer declarations carry Rust borrow semantics — `T *p = &x;` (shared) / `T *p = &mut x;` (exclusive); deref `*p`; borrow registration/release is lexical (released at end of enclosing block). | SPEC fixes no syntax for references (OPEN_QUESTIONS Q2); reusing `T *p` keeps HolyC surface (L10 `class`, HolyC lineage) while runtime enforces XOR rule (§2.3). Lexical release is the conservative, predictable choice. |
| D010 | Strictness: `#![ownership(off\|loose\|strict)]` as file-level attribute or as a statement applying to the remainder of the enclosing block; default `strict`. `off` = no checks emitted; `loose` = move tracking only; `strict` = move + borrow + div-by-zero checks. Value headers still exist when `off` (layout is global; only check *calls* are skipped). | SPEC §2.3 requires file/block levels and measurable `off` overhead reduction; keeping layout invariant across strictness levels avoids ODR-style mismatches between units in the REPL. |
| D011 | `U0` is zero-sized: 0 bytes in locals/fields/params; params/returns of type `U0` pass nothing; a bare `U0 x;` occupies no slot. Verified by checker layout unit tests (Phase 4). | SPEC Component E: "U0 as a true zero-sized type … verify zero size in tests" (distinct from Rust `()` which is also ZST — here the emphasis is *verified*). |
| D012 | try/catch implementation: runtime jmp-buffer stack; `try` saves `{rsp, rbp, catch_addr}`; `throw` (value: `I64` code and/or `Str` message) longjmp-style restores and lands in handler; uncaught throw aborts the *unit* with a diagnostic; no destructors exist in v1 so unwinding leaks nothing except arena memory (region-freed). | SPEC L9 + "diagnostics over crashes" (Part 7.5); with our own stack convention (D006) rsp-restore unwinding is exact and trivial; arena allocation bounds any leak. |
| D013 | REPL persistence model: top-level variables become runtime **globals** (name→slot), functions register in a **function registry**, classes in a **type table**; every REPL line is one compilation unit executed on a persistent 64 MiB-stack worker thread; runtime errors abort only the current unit. | L4 (top-level statements execute) + Phase 5 (define fn, call later); worker thread isolates guest stack usage and gives throw-to-top a landing pad; unit-abort keeps the session alive after diagnostics (§2.3 "live diagnostic … instead of a crash"). |
| D014 | `#exe {…}`: compiled+executed in-place via the same pipeline with stdout captured; captured text is re-lexed/re-parsed and spliced at the `#exe` position; nesting depth capped at 8. | SPEC Phase 5 Task 3 mandates "invoking the same JIT on a sub-AST"; cap prevents runaway compile-time recursion (diagnostic on exceed). |
| D015 | Function calls compile through per-function **indirection cells** (`call [cell]`); hot-patching swaps the cell target atomically (single aligned 8-byte store), old code stays mapped. | Phase 6 Task 3 requires atomic pointer swap with system continuing to run; one extra memory indirection per call is negligible against the ≤50ms/latency gates and non-goals on speed. |
| D016 | Phase 6 delivery: **host-side hot-patch simulation** (sanctioned fallback in SPEC Phase 6 risk note), with scripted demo in CI; real QEMU kernel attempt only if simulation lands early (see OPEN_QUESTIONS Q5). | No `qemu-system-x86_64` in build env; SPEC: "A working simulation is an acceptable v1 deliverable; a broken kernel is not." |
| D017 | All guest heap allocation via bump/region arena with canaries; builtin `HeapCheck(): I64` walks canaries for the Phase 6 "post-edit heap integrity check". | SPEC Component E ("bump/region allocator") + Phase 6 exit criteria; canary walk is the cheapest honest integrity check. |
| D018 | Numeric conversions are implicit (HolyC-style) between int/float widths in expressions, assignments and arg passing; explicit cast syntax `(T)expr` also provided. | SPEC is silent (Part 7.1: choose simplest, log it); F64 (L1) is unusable in practice without int↔float coercion; casts documented in LANG_SPEC §3. |
| D019 | `switch`: cases do **not** fall through (implicit break, HolyC semantics); `case a...b:` ranges; comma lists `case 1, 2:`; `default:` optional; `break`/`continue` obey nearest enclosing switch/loop as in C. | L6 says "implicit cases + ranges" (HolyC source column); HolyC semantics = no fallthrough — documented explicitly in LANG_SPEC §6 to satisfy Principle 3. |
| D020 | Variadic view: inside a variadic function, `argc` = total args passed (named + variadic), `argv[i]` = I64 view of the i-th 8-byte arg slot; F64 args passed to variadics are visible only via raw bits in v1 (LANG_SPEC §5 limitation; OPEN_QUESTIONS Q6). | L3 mandates argc/argv; D006's stack convention makes this zero-cost; the F64 limitation is documented rather than silently broken. |
| D021 | Indexing exists only for `argv[i]` and `Str[i]` (yields U8 as I64); arrays/pointer arithmetic are out of v1 (quarantined in FUTURE_IDEAS). | Not in the frozen L1–L11 table (Part 2.4: "Anything not in this table is out of scope"); argv indexing is *required* by L3, Str indexing is the minimal useful surface for L5/L8 demos. |
| D022 | `class` = value type: `class Point { I64 x; I64 y; };` locals are stack slots `[header][fields…]` (all fields 8-byte slots), member access `p.x` auto-derefs pointers (HolyC style); no `new`/`delete` in v1. | L10 mandates only the `class` keyword; heap construction is not in the frozen table → FUTURE_IDEAS; uniform 8-byte field slots keep layout math trivial and are documented. |
| D023 | `Print(...)` prints each argument formatted by its static type (Str raw bytes, signed/unsigned decimal, F64 shortest round-trip, U0 skipped, class `{field=…}` from Phase 4); no format strings in v1; output flushed immediately; bare-`Str` expression statements route through the same machinery (L5). | Spec mandates only a "print builtin" (Phase 3 Task 2); value-printing is the simplest documented semantics; format strings quarantined (FUTURE_IDEAS). Immediate flush is required by "liveness" (Principle 2). |
| D024 | Call arguments are evaluated strictly left-to-right into a pre-reserved stack arg block (`sub rsp,8n` → store → `call` → `add rsp,8n`). | Preserves C/HolyC evaluation order AND makes `argv` a contiguous ascending view (L3) with zero copies; the arg block *is* the callee's arg area. |
| D025 | Functions may return Move types (`Str`/class) by bitwise copy; the source frame dies at return so no use-after-return is possible; returning a *borrow* of a local (`&x`) is a conservative compile-time diagnostic (C04x). | Keeps move semantics sound without heap promotion machinery in v1; lifetime escape is the one case where a static rule beats a runtime trap (documented LANG_SPEC §7). |
| D026 | `switch` compiles to a cascade of compares (ranges = two compares); no jump tables. | Simplicity (Principle 1) and §1.3 explicitly waives performance parity; revisit only with benchmark evidence. |
| D027 | try/catch/throw + trap trampoline (saved rsp/rbp/landing, `jmp`) implemented in Phase 3 although L9 is scheduled Phase 3/4. | The same trampoline is required for Phase 3's "diagnostics over crashes" (stack overflow, div-by-zero, index-oob must trap, not SIGSEGV); building it once now avoids rework. |
| D028 | Generated-code calling convention detail: variadic callees receive a hidden `argc` slot at `[rbp+16]`, real args start at `[rbp+24]` (`argv` base); non-variadic callees take args at `[rbp+16]`. | Callee-side `argc/argv` become two frame offsets — zero runtime bookkeeping (L3); both ends know variadic-ness statically from the resolved signature. |
| D029 | Class redefinition in a live session: identical field layout → silently reuse the existing type; different layout → diagnostic C029. | REPL re-runs of the same file are the normal workflow; layout changes would invalidate existing instances, so they are rejected (conservative, Part 0 rule 5). |
| D030 | "Every value carries a header" (§2.3) is realized as: movable values (`Str` blocks, class instances) carry in-band headers {state, type_id, borrow}; borrow bookkeeping for *all* addressable places (incl. scalars/params) goes through the runtime ownership tracker side table; Copy scalars need no move state. | In-band headers on every integer slot would tax the common case for no diagnostic gain (scalars cannot be moved); the side table is the §2.2E "ownership tracker" component. Header contents match the spec fields. |
| D031 | Guest program output → stdout (flushed per print); runtime/compiler diagnostics → stderr, mirrored into `Rt.diag_log` for programmatic assertions. | Keeps `hr file.hr > out.txt` clean, makes CI assertions exact, and preserves the TempleOS feel interactively (both stream to the terminal). |
| D032 | v1 borrow enforcement points: conflicts trap at borrow *creation* (`&`/`&mut`) and at *writes*; reads through a shared pointer while an exclusive borrow exists are permitted (weaker than Rust's compile-time NLL). | Runtime checking cannot attribute a read to a specific borrower without per-pointer identities; enforcement at creation+write catches every XOR violation at its origin (documented in LANG_SPEC §7; revisit in FUTURE_IDEAS if needed). |
| D033 | Borrows still registered when a `throw` unwinds past their scope are dropped from compiler bookkeeping WITHOUT releasing their tracker entries; entries die at the next `unit_enter` (tracker cleared per unit). | Releasing at catch time would compute keys from dead frames (rbp-relative) and could decrement *wrong* live entries — an unsound direction. Leaked entries can only cause extra (conservative) conflict traps, never missed ones. |
| D034 | Pointer mutability: declared `T *p` types carry no `mut` marker; exclusivity is inherited from the initializer (`&mut`). Coercions: &mut→& demotes silently; &→&mut is compile error C045; function parameters are shared. Redeclaration type-equality ignores the mut flag (storage-identical). | The frozen syntax table (L1–L11) fixes no `&mut T` type syntax; inheritance from the borrow expression gives Rust-equivalent expressiveness at declaration sites with zero new surface syntax. |
| D035 | L5 auto-print fires for bare `Str` expression statements EXCEPT assignments (`s = "x";` is silent, still feeds the REPL echo). | `x = "s";` printing the string surprised nobody in HolyC because HolyC echoes are REPL-scoped; assignment-echo in files broke the ownership matrix and is universally unexpected in file execution. Found by tests, documented here per Part 7.1. |
| D036 | REPL streams: guest output + value echo → stdout; banner/prompts/diagnostics → stderr; `session.log` in cwd records inputs, diagnostics, and per-statement latency; prompts only when stdin+stdout are ttys (`isatty` declared manually — no crates). | Scripted sessions (the spec's own exit criterion) need machine-clean stdout; latency-in-log makes the ≤100ms p95 gate auditable after the fact instead of re-measured. |
| D037 | Hot-patch transport: ONE control channel from the worker thread to the host carrying `Done` and `Patch{src, ack}` messages; the guest `HotPatch` builtin blocks on its ack while the host compiles on the main thread (Session stays single-owner). Patch compilation refuses `#exe` (would need the blocked worker → deadlock). | Avoids re-entrant &mut Session access and any locking; deadlock-free by construction; the running kernel's state (globals, frames, stack) is untouched — only cells swap. Verified by `kernel_survives_bad_patch` + `hotpatch_rejects_exe_and_keeps_running`. |
| D038 | Real-kernel boot route: **multiboot1 flat binary via QEMU `-kernel`** (a.out-kludge header fields from linker symbols), linked ELF64 then `objcopy -O binary`. QEMU 7.2 empirically rejects multiboot ELF64 ("give a 32bit one"); the kludge route keeps ONE toolchain for the 32-bit asm boot and the 64-bit Rust kernel. Critical lesson pinned in linker.ld: **`.got`/`.got.plt` must fall inside `[load_addr, load_end)`** — orphaned GOT beyond `_kernel_load_end` is never copied to RAM → wild indirect jumps (the first kernel crash). |
| D039 | Boot page tables + 8 MiB kernel stack live in a dedicated `.boot_tables` NOBITS section placed OUTSIDE `[_kernel_bss_start, _kernel_bss_end)`. | The explicit in-kernel bss-zero loop must never touch the page tables backing its own writes (that was the second kernel crash: #PF at exactly bss_start+4K = the pml4→pdpt boundary). |
| D040 | Keyboard: PS/2 **polled** (status 0x64 / data 0x60) in v1, serial RX as a second key source; IDT/IRQ1 deferred to FUTURE_IDEAS F16. Recorded as DEGRADE from the spec's "interrupt handlers" bullet. | Polling is deterministic, ~1 ms latency (≪ human typing), and removes PIC/IDT/ISR risk from the flagship demo — the risk note's "working > broken". Serial doubles as the scripted-CI channel (`-chardev socket`), keeping the transcript test hermetic. |
| D041 | Kernel memory model v1: identity-map first 1 GiB with 2 MiB RWX pages; fixed physical heap 32–224 MiB (`-m 256M` pinned in CI); bump allocator, no free (arena philosophy D017 extended to the whole kernel). | Matches the spec's RAM-disk-era simplicity (§1.3); generated code needs no W^X dance because the mapping is uniformly RWX (documented simplification; NX/W^X is a future hardening idea, not a v1 goal). |
| D042 | In-kernel HotPatch takes the DIRECT path (no channels/threads): `Rt.host_sess` holds the Session pointer; `rt_hot_patch` compiles on the spot (single-core, no aliasing at runtime). `#quit` = 8042 reset pulse + QEMU `-no-reboot` → deterministic CI termination. | The host's channel dance (D037) exists only to protect a multi-threaded Session; the kernel is single-address-space by nature, so the simpler path is the correct one. |
| D043 | **Host runtime ported to Windows** (TempleOS-RS Phase 0). Four contained changes, none of which alters Linux behaviour: (1) a `code_mem` module — `VirtualAlloc`/`VirtualProtect` on Windows, the original `mmap`/`mprotect` pair verbatim on unix, behind one `alloc_rw`/`make_rx` pair; (2) every JIT-facing callback is now `extern "sysv64" fn` instead of `extern "C" fn` (the 16 `FnTable` fields, the ~17 `rt_*` implementations, both `transmute`s); (3) `isatty(0/1)` → `std::io::IsTerminal`; (4) `--dump-code` writes `std::env::temp_dir()/blob.bin`, and `tests/kernel_boot.rs` probes for a *working* python (`python3`/`python`/`py`) rather than trusting the name. | v1 is "x86-64-Linux-only by design" (SPEC §1.3) and INSTALL.md's answer for Windows is WSL2 — but the owner's machine is Windows 10 with no WSL distro, no in-process elevation, and 4 GB of RAM, so the documented path demanded an elevated install plus a reboot before a single line could be compiled. The JIT's real contract is *"x86-64 machine code following the SysV ABI"*, not "Linux"; the Windows x64 ABI passes args in RCX/RDX/R8/R9, so the honest fix is to **name the convention explicitly** rather than touch codegen. On `x86_64-unknown-linux-gnu`, `extern "sysv64"` *is* `extern "C"`, so the change is a no-op there, and the kernel target (`x86_64-unknown-none`) is untouched. Verified: 97/97 release tests green on Windows, zero warnings, `hr demos/hello.hr` prints `Hello, world`. |
| D044 | **Kernel build + kernel-CI transport ported to Windows** (TempleOS-RS Phase 0). No GNU `as`/`ld`/`objcopy` required: `boot.S` is assembled by rustc's integrated LLVM assembler via `kernel/bootasm.rs` (`global_asm!(…, options(att_syntax))`), and `rust-lld -flavor gnu -T linker.ld --oformat=binary` replaces the `as --64` + `ld` + `objcopy` chain (`kernel/build.ps1`; `build.sh` left untouched for Linux). `tools/kernel_ci.py` drives QEMU over **TCP loopback** chardevs (QEMU's Windows build has no `AF_UNIX`), writes scratch files to the system temp dir instead of `/tmp`, and mirrors serial traffic into a chardev `logfile`. | A Windows MinGW `as`/`ld` emits PE/COFF, not the ELF64 the multiboot flat-binary route depends on, and rustup already ships everything actually needed. Two porting failure modes were located by instrumentation rather than guesswork: (a) Rust's `global_asm!` defaults to **Intel** syntax, so a GAS file needs `options(att_syntax)`; (b) the guest prints `kernel: halting (reset)` and *immediately* pulses reset, and a loopback TCP teardown (RST) discards the peer's receive queue, so the transcript's final marker was reliably lost until the serial stream was mirrored to QEMU's synchronous `logfile`. Result: `KERNEL-CI: PASS`, boot 1.5–2.8 s against the < 5 s gate, with hot-patch, `HeapCheck()=1`, PS/2 `sendkey` and a VGA screendump all asserted. |
| D045 | **Filesystem storage lives on `Rt` (one FS per `Session`); only raw storage is a builtin.** `Fs { entries: Vec<FsEntry> }` holds `name: String` + `data: Vec<u8>`, capped at 64 entries × 16 KiB, and is appended as the **last** field of `Rt` so every `offset_of!`-derived codegen offset above it is untouched. Four primitives — `FsWrite`, `FsRead`, `FsList`, `FsDelete` — plus `StrLen`/`StrEq` (D047) are the entire Rust-side surface. `FsRead`/`FsList` mint `Str` blocks from an arena the FS owns. | T1.2 asks for FS primitives as builtins while G1 forbids "hardcoded FS logic", so the split is storage-vs-policy: the runtime knows bytes and names, and every naming rule, glob, listing format and message is HolyRust in `/TOS/Files.HR`. A process-global store was rejected because `cargo test` runs tests on parallel threads (races), and because a per-`Session` FS gives the kernel exactly one filesystem while giving host tests isolation. Giving the FS its own arena means `FsRead` needs no `&mut Session` — which would alias the session while the guest thread is running. `ret_ty()` had to be introduced because `check_call` hard-coded `I64`, which would have made `Str s = FsRead(p);` uncompilable. |
| D046 | **Boundary of T1.4: the kernel keeps the read/compile loop; the *command processor* moves to HolyRust.** `kernel/src/shell.rs` reads a line, decides lexically whether it is a bare command word, and otherwise compiles it. If it is a bare word, the kernel evaluates `Sh("<word>");` — `Sh`, `Help`, the command table, aliases and every message live in `/TOS/Shell.HR`. Commands taking arguments are called as the HolyRust functions themselves (`Cat("/TOS/Files.HR");`), which is exactly the form SPEC_TOS §5.2's own CI snippets use. | Reading a line and invoking the JIT *is* what a JIT host is; a "shell fully written in HolyRust" cannot own its own input loop without a `Str`-building, file-reading, self-compiling primitive set that v1 does not have (F18). What genuinely can move does move: no command name, argument rule or message remains in Rust. The routing decision is deliberately *lexical only* (one identifier token, `Eof` filtered), so no policy leaks into the kernel, and the word is a validated identifier, so the generated `Sh("...")` call is injection-free by construction. The unquoted-argument form (`cat /TOS/x`) is quarantined to F18 rather than faked. |
| D047 | **Two new string primitives, `StrLen(Str) -> I64` and `StrEq(Str, Str) -> I64`, as builtins.** Non-consuming, and they only read block headers/bytes. | Forced by measurement while writing `/TOS/Files.HR` (PROGRESS TOS-P1.2): (a) `Str[i]` correctly traps at `i == len`, so the NUL terminator is unreadable and v1 offered no other way to find a string's end — without `StrLen`, *no* string walk could terminate; (b) a `Str` **variable** is moved when passed to a user-defined function (D008), so HolyRust alone cannot test one string against several literals and a glob pattern cannot be re-passed to a matcher per iteration — `StrEq` is the non-consuming comparison that makes both possible. Both mirror TempleOS's own `StrLen`/`StrCmp` builtins, and neither contains filesystem or shell *policy*: they are the minimum a language with a `Str` type must expose before a kernel service can be written in it. The alternative (relaxing the `i == len` bounds check so the NUL becomes readable) was rejected because it would weaken a memory-safety guarantee to buy convenience. |
| D048 | **VGA mode 12h is programmed by direct register writes, not by BIOS/VBE calls in `boot.S`** — a deliberate deviation from the letter of T2.1. `kernel/src/gfx.rs` sequences the miscellaneous output register, Sequencer, CRTC (releasing then re-asserting CR0-CR7 write protection), Graphics Controller, Attribute Controller and the DAC (the 16 EGA colours written explicitly). The framebuffer is planar 640x480x16 at 0xA0000; single pixels are written in **write mode 2** (colour expands across the four planes) with a **read of the byte first to load the four plane latches** before the masked write. | `boot.S` is entered by the multiboot loader in 32-bit protected mode, so `INT 10h` would require dropping back to real mode — machinery that risks the boot path Phase 0 certified, for a mode that port I/O sets exactly. Keeping it in Rust also keeps the mode-set next to the drawing code and testable through the same QEMU screendump oracle. Two register-level lessons were measured, not assumed, and are pinned in `gfx.rs`: write mode 0 can only ever produce colours 0 and 15 (a data byte's bit *j* reaches every plane at position *j*), and with a bit mask the controller merges into its latches, so a stale latch silently reverts bits an earlier plot wrote **in the same byte** (two pixels sharing a byte → the first disappears). |
| D049 | **Graphics follows the Phase 1 split: `GfxInit`/`GfxClear`/`Plot`/`GfxChar` are runtime builtins forwarded to kernel-installed `GfxHooks`; `Line`, `Rect`, `FillRect`, `Circle`, `FillCircle`, `TextOut`, `TextCentered`, `GfxDemo` are HolyRust in `/TOS/Graphics.HR`.** The runtime contains no driver; the kernel installs the device at boot, exactly like `hr_out`'s output hooks and `KERNEL_CHUNK`. `Plot` returns 1 when a device exists and 0 otherwise, and `GfxInit` emits a diagnostic when there is none. The 8x8 font is compiled in (`kernel/src/font8x8.rs`, generated by `tools/gen_font8x8.py` from the public-domain font8x8 table). | T2.2 lists five drawing names "as HolyRust builtins", but SPEC_TOS §2.3 wants kernel services to be *guest code*: only the primitives that must touch hardware belong in Rust, and every shape is then editable like any other file. A runtime-resident VGA driver would also have to be compiled into the host build, where it is meaningless — the hook indirection lets the host suite report honestly that it has no display instead of faking one. The font is compiled in rather than read from VGA plane 2 so glyph rendering does not depend on firmware state; the generator exists so the table is reproducible rather than hand-transcribed. |
| D050 | **Build staleness is defended against explicitly.** `kernel/build.ps1` and `tools/cargo.ps1` delete a target directory that contains files timestamped in the future before invoking cargo. | This host's wall clock jumps **backwards**: build outputs were measured at 17:08 while the clock read 16:22, so cargo judged every newly edited source older than its own outputs, printed `Fresh hr-kernel`, and silently re-linked the previous objects. The symptom was not an error but a lie — three genuinely different `gfx.rs` implementations produced byte-identical kernels, so two real graphics fixes looked inert. Touching sources cannot fix it (their timestamps are still behind the future-dated outputs); removing the impossible-in-the-future target can. Recorded because the general lesson belongs in the project, not in one debugging session: *a green test means nothing until you have confirmed the code under test was compiled.* |
| D051 | **Time is a polled PIT counter, and its resolution is documented as a limit rather than hidden.** `timer::poll()` accumulates wraps of the 8254 channel-0 down-counter (rate generator, divisor 1193 → one counter unit ≈ 1 ms) and is called from the shell's idle loop *and* from `Time()`/`Sleep()` themselves. `Sleep(ms)` is a busy wait on that clock; `Date()` reads the CMOS RTC (update-in-progress guard, BCD-or-binary honouring, and 0 rather than a wrong date when the fields are implausible). Both are exposed through kernel-installed `TimeHooks`, like `GfxHooks`. | SPEC_TOS puts interrupts out of v1 scope, and a polled clock's accuracy is bounded by how often it is polled — a fact worth *stating* because it shows up in measurement: on this TCG host `Sleep(100)` observes ~635 ms, since each poll is three port-I/O operations and emulation makes them expensive, so the wait overshoots. The alternative (claiming millisecond precision) would be a lie the CI gates could not detect. Returning a real elapsed time from `Sleep` also lets a caller verify its own wait instead of trusting it. |
| D052 | **The keyboard poller ignores bytes flagged as auxiliary.** `kbd::poll()` now checks status bit 5 and returns without reading 0x60 when the pending byte came from the PS/2 mouse, leaving it for the mouse driver. | A latent defect exposed by Phase 3: reading 0x60 whenever the output buffer was non-empty was correct while the 8042 had only a keyboard, and became a byte-stealing race the moment the aux port was enabled — the keyboard poller would eat mouse packets and the mouse poller would eat key scancodes. Nothing in the old code was "wrong" until a second device existed, which is precisely why the fix is recorded: the contract of a shared controller belongs in the code, not in the accident that only one device was attached. |
| D053 | **The PC speaker is a hook-backed builtin, and the *serial tone log* is the declared evidence channel.** `sound::beep` programs PIT channel 2 as a square-wave generator, gates it into the speaker via port 0x61 bits 0-1, writes `[tone] <freq> Hz for <ms> ms` through `hr_out` **before** waiting, then silences. `Music`/`Scale`/`Fanfare`/`Chirp` are HolyRust in `/TOS/Sound.HR`; `Random(n)` comes from `RndHooks` (xorshift64\* stirred by `rdtsc`) and is clamped to `0..n` by the runtime; the eight verses and the dispatch live in `/TOS/Oracle.HR`. | A headless CI cannot hear, and SPEC_TOS G4 explicitly accepts a serial log of frequency changes as the evidence — so the log is part of the design, not a substitute for testing. Logging before the wait also keeps the transcript ordered against the drawing. The clamp is deliberate: the oracle indexes a word list with `Random`, so a misbehaving entropy source must not be able to turn into an out-of-range access in guest code — a kernel service must not be able to crash the kernel by returning nonsense. |
| D054 | **Idle-loop work must be demand-driven, and every boot "wait for ready" loop is tightly bounded.** The mouse cursor repaints only when `DIRTY` (set by movement, `show`, or a wholesale repaint), not on every poll; `Date()`'s update-in-progress guard and the 8042 controller waits are bounded at 10k iterations instead of 1,000,000/100,000. | Both were measured failures, not hypotheticals. `mouse::poll()` runs in the shell's idle loop, and an unconditional repaint costs ~250 port operations per iteration — enough to starve the guest until the Phase 2 pixel assertions (which had passed for two phases) started failing; repainting something that has not moved is pure cost. Separately, boot regressed from ~1.8 s to 6.5 s against the < 5 s gate purely because two unbounded-ish spins each burned port I/O under emulation: a "wait until the device is ready" loop with a six-order-of-magnitude ceiling is a landmine, and the bound should be sized for the worst case you are willing to pay on *every* boot. |
| D055 | **`#include "path"` is a strict, textual, pre-parse pass that resolves against the session's filesystem first.** `pipeline::expand_source` runs before `expand_program`, splices the included file's source into the unit, recurses with the same depth cap as `#exe` (8), reports a missing file as a positioned `C094`, and treats an include cycle as a depth error rather than a hang. The directive must occupy a whole line (only whitespace or a `//` comment after it). Lookup order is `Session`'s in-memory filesystem, then the host disk under `cfg(feature = "host")`. | The directive genuinely means "this source becomes part of this unit", so a textual splice is the honest implementation, and it is what lets the OS include *its own* storage — the filesystem the OS booted from — rather than a host directory that may not exist on the machine the OS is running on. The whole-line rule is what keeps it from firing inside a string or a comment; a scan that matched mid-line would be a permanent source of surprising behaviour. The depth cap is inherited from `#exe` because an unbounded recursive include is a hang, and a hang is worse than an error. |
| D056 | **The editor's buffer lives on `Rt`, beside the filesystem, and only its plumbing is Rust.** `EdBuf { path, lines, dirty }` sits next to `fs`; seven primitives (`EdOpen`, `EdLines`, `EdLine`, `EdSet`, `EdFind`, `EdSave`, `EdClose`) do the storage work, and `/TOS/Editor.HR` supplies every command (`Ed`, `EdShow`, `EdReplaceLine`, `EdSaveAndReport`) in HolyRust. `EdSet` refuses out-of-range indices rather than extending a file, and `EdSave` writes the whole buffer back through the same `Fs` the OS boots from. | The file most often being edited here is the OS's own source, so the buffer has to be part of the *live machine*, not a host-side structure — putting it on `Rt` makes "the file you are editing" the same object the running system reads. Keeping the commands in HolyRust is the Phase 1 split again (D045): Rust owns bytes, guest code owns vocabulary, so the editor's behaviour is editable with the editor. Refusing bad indices is the same principle as `Random`'s clamp (D053): a user-facing service must not be able to corrupt data through a bad argument, and one line of validation is cheaper than a corrupted OS. |
| D057 | **Guest code can read the real keyboard: `SimKey()` gains a fallback key source.** `KeyHooks { poll: fn() -> i64 }` is installed by the kernel (one `kbd::poll()`, translated to a character code, −1 when nothing is pending); `rt_sim_key` drains the simulated queue first so scripted demos stay deterministic, then consults the hook. No new builtin was added — `SimKey()` simply means "the next key, from wherever the machine has one". | Phase 6 gave guest code `SimKey()` for *simulated* keystrokes, and nothing noticed that the real keyboard was unreachable: the only caller of `kbd::poll()` was the shell's own line reader. That is invisible until a guest loop needs input while it runs, which is exactly what a flight simulator does — and the Phase 7 request ("throttle via keys") cannot be honest without it. Extending the existing builtin rather than adding a second key API keeps one answer to "what key is pending", so the shell and a guest loop can never disagree about the device. This is the one place Phase 7 added Rust, and it is a defect fix: a guest program could not read the keyboard at all. |
| D058 | **Reading the mouse position samples the device.** `mouse::x()`/`mouse::y()` call `poll()` before returning the tracked position. | The position was only ever updated by the shell's idle loop, so as soon as guest code took over the machine the cursor position froze at its last value — a flight sim would have flown on a stale stick. "Read the position" should read the device; the same principle already applied to `Time()`/`Sleep()`, which poll the PIT themselves (D051). The cost is one status-port read plus a possible cursor redraw, and `poll()` already returns immediately when nothing is pending. |
| D059 | **`boot.S` sets `CR4.OSFXSR` and `CR4.OSXMMEXCPT` alongside `CR4.PAE`.** | A latent Phase 0 defect with a spectacular symptom: `/TOS/Flight.HR` killed the kernel on boot. Without `OSFXSR` every SSE instruction raises #UD, and with no IDT the machine dies silently — so F64 *values* worked (they can be copied as bit patterns) while F64 *arithmetic* was fatal. Five phases never noticed because no `/TOS` code had ever done arithmetic on a float. `OSXMMEXCPT` is set with it so a genuine floating-point fault arrives as #XF, distinguishable from an illegal opcode. This is a *boot* bug, not a language limitation: the JIT had been emitting correct SSE the whole time. |
| D060 | **The 8x8 font is read LSB-first, and the CI checks a glyph's *shape*, not its pixel count.** `gfx::glyph` tests `bits & (0x01 << rx)`; the convention is documented in the kernel, in `font8x8.rs` and in the generator. The CI renders `/` and asserts that its top row lights the right half and its bottom row the left half. | `font8x8_basic` stores bit 0 as the leftmost pixel, but the table's generated header claimed bit 7 was, and `glyph` followed the comment — so every glyph in graphics mode was drawn mirrored from Phase 2 to Phase 7. Nothing caught it because every graphics assertion counted lit pixels, and a mirrored glyph has *exactly the same count*: the suite was green while five phases of screenshots showed mirrored text. Counting pixels cannot see shape, so the regression test reads shape — a check that fails for the mirrored glyph and passes for the correct one, with no font data duplicated into the test. |
